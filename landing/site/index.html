What it does

Separate accounts that never bleed into each other.

Truly isolated

Every Desktop profile and every CLI account gets its own data directory — separate login, history, cookies, and settings. Nothing from one account is ever visible to another.

Run them together

No single-instance lock, no signing out. Keep several Desktop windows and several Claude Code terminals live at the same time.

Claude Code, per account

Each CLI account carries its own real Claude sign-in — full email and org identity — and refreshes on its own. Type claude and it runs as the right account, every time.

Open any project in your IDE

Bind a folder to an account and Personae wires CLAUDE_CONFIG_DIR into VS Code, Cursor, Windsurf or Antigravity — every terminal opens Claude Code already signed in to that account.

Colour is identity

A tinted icon and accent per profile, plus a green dot when it's running. Know which account you're in at a glance.

Made for the keyboard

⌘N for a new one, ⌘L to launch, ⏎ to open, ⌫ to remove. Search and switch without touching the mouse.

Local & private

No account to create, no server, no telemetry. Personae orchestrates the Claude you already installed — everything stays on your machine.

Feather-light, survives updates

A tiny native app built on Tauri — a few megabytes, not another Chromium. It wraps your installed Claude Desktop and Claude Code, so it keeps working after every auto-update.

Three steps

From one account to many in under a minute.

STEP 1

Add a profile or account

“Work”, “Personal”, a client — whatever you juggle. Choose Desktop for a full app window, or CLI for Claude Code in the terminal.

STEP 2

Sign in once

Personae opens Claude's own secure sign-in. A Desktop profile keeps its window logged in; each CLI account gets its own real login that refreshes itself.

STEP 3

Launch — or open a project

Launch the window, or point a CLI account at a project folder and Personae opens your IDE with Claude Code already signed in. Repeat for as many accounts as you need.

FAQ

Running multiple Claude accounts, answered.

Can I run two (or more) Claude accounts at the same time?

Yes. Personae has no instance limit — open as many Claude Desktop windows and Claude Code terminals as you like, all at once, each signed in to a different account.

Does it work with Claude Code (the CLI)?

Yes. Create a CLI account for each login; each keeps its own real Claude sign-in — full email and org identity — and runs independently. Open a project and its IDE terminals launch claude already signed in to that account, so you never log out to switch.

How do I run multiple Claude accounts on a Mac?

Install Personae, add a profile or CLI account for each login (Work, Personal, a client…), then launch. Every one is fully isolated with its own login and history — sign in once and it stays signed in.

Which IDEs does the CLI integration support?

VS Code, Cursor, Windsurf, and Antigravity — any VS Code-family editor. Personae sets CLAUDE_CONFIG_DIR for the project folder so its terminals use the right Claude Code account automatically.

Does it work on Windows?

Desktop profiles run on macOS 11+ and Windows 10+. Claude Code (CLI) accounts run on macOS, with Windows support in beta.

Is my data private? Does Personae see my logins?

No. There's no account, no server, and no telemetry. Personae only orchestrates the Claude you already installed; each profile and account's data stays on your machine, isolated from the others.

Will it break when Claude updates?

No. Personae wraps your installed Claude rather than repackaging it, so it keeps working after Claude's auto-updates.

Is Personae free? Is it official?

It's free. It's an independent companion tool — not affiliated with, or endorsed by, Anthropic.

First time opening it? Read this

macOS — right-click the app and choose Open, then confirm. (Or go to System Settings → Privacy & Security → Open Anyway.)

Windows — if a blue “Windows protected your PC” box appears, click More info → Run anyway.

Personae isn’t code-signed yet, so the OS shows this one-time warning. It’s safe — the code is public and everything runs locally, with no account or telemetry.
